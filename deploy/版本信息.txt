v16 GPD 电压升降循环：
- 确认 GPD2303S 的 `ISET1/ISET2` 可真实设置并回读，它表示对应通道的电流上限；界面改名为“电流上限 (ISET)”，不增加设备不存在的独立限流开关。
- 辅助电源页面新增“电压升降循环”：可选 CH1/CH2，设置上升目标、下降目标、上升速率、下降速率和有限循环次数，速率单位为 V/s。
- 启动后先从设备当前 VSET 按对应速率运行到下降目标，再完成指定次数的“下降目标→上升目标→下降目标”；正常结束停在下降目标。
- 斜坡每一步使用独立 VSET 写入和回读，根据实际经过时间计算目标电压，避免把串口处理时间叠加成持续速率误差。
- 电压循环只改变所选通道 VSET，保持 ISET 和输出 ON/OFF 状态；停止时保持最后一次确认电压。电压循环与原循环关断功能互斥，断开或退出前会先停止。
- GPD 参数和自动功能区域改为均匀布局，运行期间锁定可能冲突的通道、参数、单次输出和读取按钮。

v15 CAN 收发筛选与布局调整：
- CAN 页面暂时移除 DCDC 控制和模板组区域；退出时不再自动发送隐藏的 DCDC 关闭帧。
- 适配器配置与连接操作、通道选择与打开/关闭操作分行显示；各小区域中的输入、状态和按钮按可用宽度平均排列。
- 发送帧与接收帧合并到“CAN 收发帧”区域，成功发送记为 TX，自动接收记为 RX。
- 新增通道、十六进制 ID 和方向三类筛选；可组合筛选 CAN0/CAN1、指定 ID、TX/RX，清空显示不停止后台接收。
- 旧日志中的 `S` 表示标准帧、`X` 表示扩展帧，并非 CAN ID 内容。新版改为“标准帧 ID=7FF”或“扩展帧 ID=xxxxxxxx”，消除 `S000007FF` 的歧义。

v14 页面连接配置与滚动区修正：
- PLC 页面显示本机 IP、PLC IP 和端口；N69206 页面显示 IP、端口、设备 ID；示波器页面显示 IP 和端口。三类网络设备点击“连接”时使用当前界面值。
- N69206 页面新增 CC、CV、CR、CP 四个独立量程下拉框；点击“应用模式参数”时使用当前模式对应量程。
- System.ini 删除所有 IP、端口和 N69206 量程项，只保留 PLC 高级连接参数、设备型号、超时和产品采集参数。
- GPD2303S、GDM9061、PA333H 的串口改为可下拉选择、也可手输；默认值仍为现场已确认的 COM12、COM13、COM4。
- 所有设备页均把连接状态和连接/断开按钮放在连接配置之后。
- 串口、N69206 和示波器驱动改为在每次连接时按当前配置重新创建传输对象，界面修改的地址和串口会真实用于连接。
- GPD2303S 保留设备真实支持的 ISET 电流设定，界面不再把它描述成独立“限流功能”。
- 设备内容区启用边界裁剪和受约束滚动，移除右侧日志的固定最小高度；CAN 等页面的滚动条轨道保持在当前可见工作区内。
- 修正异步安全关闭完成后立即再次调用窗口关闭导致的 WPF 异常；现在退出操作排入下一次界面调度，程序可正常返回退出码 0。

v13 CAN 自动接收与循环发送：
- CAN0/CAN1 任一通道打开后自动启动后台接收，持续轮询全部已打开通道；收到的帧按毫秒时间和 CAN0/CAN1 标识实时追加到“CAN 接收帧”区域，无需再点击“接收 500 ms”。
- 自动接收空闲时每 20 ms 轮询，每个通道每批最多读取 256 帧；收到数据后快速继续读取，关闭通道、断开适配器或退出前安全停止。
- 单帧 Data 支持连续十六进制 `01020304`、空格格式 `01 02 03 04` 和 `0x01,0x02`，不再要求手工敲空格。
- 新增数据长度。经典 CAN 可选 0～8 字节；CAN FD 可选 0～8、12、16、20、24、32、48、64 字节。输入少于长度时尾部自动补 00，超过长度时明确报错。
- 新增发送间隔（ms）：0 表示只发送一次；大于 0 表示按该间隔持续发送，并显示累计发送帧数。“停止循环发送”只停止周期发送。
- 循环发送按相邻帧起始时间计算间隔，发送耗时会从等待时间中扣除；发送、自动接收仍通过同一个驱动互斥入口串行执行。
- “清空接收区”只清除界面帧文本和累计数，不停止自动接收。

v12 CAN0 经典帧发送与通道保持修复：
- 根据 12:22～12:23 现场日志定位：CAN0 能启动，但 ZCAN_Transmit 返回 0；随后程序把设备状态异常作为 IOException，界面自动清除了 CAN0，形成“未点击关闭但通道自己关闭”的现象。
- ZLG 官方头文件明确规定，100U/200U 是 CAN FD 硬件，即使通道协议选择经典 CAN，ZCAN_CHANNEL_INIT_CONFIG.can_type 也必须使用 TYPE_CANFD（1）。本版已固定按 CAN FD 硬件初始化。
- 连接适配器时为 CAN0/CAN1 明确设置 protocol：经典 CAN 为 0，CAN FD 为 1；总线协议选择与硬件初始化类型分别处理。
- ZCAN_Transmit 返回 0 或设备状态异常时只记录错误和状态，不再自动清除、关闭 CAN0/CAN1；通道保持打开，只有操作员点击关闭、断开适配器或退出程序时才释放。
- 现场复验按双电脑、双 CAN 盒进行：发送端和接收端均设经典 CAN、500 kbps，两个盒子通过 CAN-H、CAN-L 和 GND 连接，终端电阻按总线两端配置。

v11 CAN 双通道与发送修复：
- CAN 收发、初始化、状态和配置改为直接调用官方 zlgcan.dll；zlgcan_wrap.dll 只为旧 LabVIEW 兼容保留。
- 单帧发送参数改为与官方 ZCAN_Transmit/ZCAN_TransmitFD 原型一致的 ref 结构体指针，避免数组封送造成发送返回 0。
- 连接适配器时先为 CAN0/CAN1 预配置仲裁/数据波特率；每个通道执行 ZCAN_InitCAN 后、ZCAN_StartCAN 前再设置该通道 120Ω，符合 200U 属性定义中的 pre/post 顺序。
- 新增“同时打开全部通道”和“关闭全部通道”，CAN0、CAN1 可同时处于真实打开状态并分别收发。
- 修复 ResetCAN 失败时通道句柄不清除的问题；断开、设备离线和重新连接都会清空旧句柄，不再把旧 CAN0/CAN1 误报为已打开。
- 发送或接收发现设备离线时，界面立即恢复为未连接状态并允许重新设置、重新连接。
- 仲裁和数据波特率界面、状态和日志统一显示为 kbps；程序内部仍按 ZLG 接口要求转换为 bit/s。
